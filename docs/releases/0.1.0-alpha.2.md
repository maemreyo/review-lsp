# Review-LSP 0.1.0-alpha.2

Status: PUBLIC ALPHA once the exact release commit passes the compatibility matrix and is published under the `alpha` dist-tag.

## Purpose

This alpha moves Review-LSP from source-only exact-candidate semantics to an admitted dependency-aware TypeScript semantic environment suitable for real code-review dogfood.

## Added

- Offline, content-addressed pnpm dependency acquisition and sealed snapshots.
- Candidate source + admitted dependency execution projections.
- Workspace entry-point completeness gates.
- Constrained plain-`tsc -p` derived declaration artifacts with compiler exit/diagnostic admission gates.
- Project-local TypeScript engine routing and `EXACT_PROJECT` evidence.
- TypeScript 7 native-LSP support with platform-runtime identity binding.
- Persistent semantic runtime reuse for repeated/concurrent review questions.
- Coordinate targeting context and richer definition bindings.
- Realistic candidate/dependency/query benchmark evidence.

## Fail-closed hardening

- Unsupported pnpm workspace YAML/glob and package `exports` shapes do not silently shrink authority.
- Dependency/projection/derived verified leases detect descendant metadata drift and force full re-verification.
- Advisory, crashed or timed-out derived artifacts never become cache authority.
- Snapshot-backed semantic sessions require the bound execution projection.
- Sandboxed TypeScript-language-server sessions do not use a cross-sandbox client-PID watchdog probe.

## Install

```bash
npm install review-lsp@alpha
npx review-lsp artifact-info
```

## Release gates

Publication is blocked unless all of these pass on the exact release commit:

- `pnpm check`;
- macOS 14 / Node 22.19 and 24.19 compatibility;
- Ubuntu 24.04 / Node 22.19 and 24.19 compatibility;
- Linux container isolation smoke;
- benchmark job;
- clean-install package smoke;
- candidate-bound independent code review and successor review for any release-blocking finding.

## Known limitations

- TypeScript is the only supported language profile.
- The dependency provider intentionally supports a strict pnpm-10/workspace/config subset and fails closed elsewhere.
- Arbitrary package build pipelines are not executed.
- Windows, remote MCP, signatures, and additional semantic operations remain outside this alpha.
- Receipts prove provenance/admission properties, not semantic correctness of the LSP answer or reviewed code.

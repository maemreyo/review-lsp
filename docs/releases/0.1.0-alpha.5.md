# Review-LSP 0.1.0-alpha.5

Status: PUBLIC ALPHA once the exact release commit passes the compatibility matrix and is published under the `alpha` dist-tag.

## Purpose

Alpha.5 hardens general TypeScript project admission without adding a new semantic operation. A supported candidate-contained project-reference graph is now parsed, bounded, content-addressed, and bound into the environment manifest that existing hover, definition, references, and document-diagnostics receipts already identify.

This is deliberately narrower than TypeScript build mode. Alpha.5 does not claim universal project-graph completeness, exact `files`/`include` ownership, arbitrary config-chain resolution, or package/build execution.

## Added

- Deterministic `EnvironmentManifest.project_references` evidence with `NONE`, `BOUND`, and `UNSUPPORTED` states.
- Candidate-contained directory reference resolution using TypeScript's established `<path>/tsconfig.json` shape.
- Explicit JSON reference targets only when they remain inside the existing admitted config-authority subset.
- Deterministic graph/config/reference digests and bounded traversal.
- TypeScript 6 and TypeScript 7 exact-engine acceptance fixtures exercising an admitted project-reference graph.

## Security and evidence boundary

- Project-reference handling parses candidate config; it does not execute project references, package scripts, or arbitrary build steps.
- Absolute paths, candidate escapes, missing or unadmitted targets, duplicate normalized edges, malformed reference shapes, unsupported fields, and cycles are rejected for strong admission.
- Every config consumed by graph admission is read through the retained-candidate verified-read path. Integrity failure propagates as candidate-integrity failure rather than being downgraded to malformed JSON.
- Config and edge SHA evidence comes from the same verified reads whose bytes are parsed.
- Existing semantic receipt schemas remain unchanged. Project-reference evidence is bound transitively through `environment_manifest_sha256`.
- `environment_binding=VERIFIED` remains an admission/provenance claim, not proof that TypeScript's semantic answer or the reviewed code is correct.

## Consumer boundary

The local MCP provider continues to expose the existing candidate/environment contract: `environment_binding`, `environment_manifest_sha256`, limitations, candidate identity, profile identity, and semantic capabilities. Alpha.5 does not add a Workbench-specific core policy or a new MCP semantic operation.

Consumer dogfood is required because project-reference admission can change the environment binding/hash/limitations already consumed by review flows.

## Install

    npm install review-lsp@alpha
    npx review-lsp artifact-info

## Release gates

Publication is blocked unless all of these pass on the exact release commit:

- targeted Alpha.5 project-reference unit tests;
- TypeScript 6 and TypeScript 7 project-reference semantic acceptance;
- `pnpm typecheck`, build, and full `pnpm check`;
- package, MCP stdio, and cache-publication-crash smokes;
- macOS / Node 22.19.0 and 24.19.0 compatibility;
- Ubuntu 24.04 / Node 22.19.0 and 24.19.0 compatibility;
- Linux container isolation smoke;
- benchmark;
- real Workbench consumer dogfood for the existing environment evidence contract;
- independent candidate-bound implementation and release-prep review with no unresolved blocking findings;
- exact tag/GitHub-prerelease/npm-pack identity checks;
- publication as `review-lsp@0.1.0-alpha.5` under `alpha` without moving `latest`;
- clean public-registry install/A-B semantic smoke.

## Known limitations

- TypeScript is the only supported language profile.
- Project references are supported only for the frozen Alpha.5 candidate-contained subset.
- Exact `files`/`include` ownership and broader TypeScript config chains remain deferred.
- Arbitrary local-directory dependencies and arbitrary package lifecycle/build pipelines remain unsupported.
- Symbols and project/workspace diagnostics remain deferred.
- MCP is local stdio only.
- Windows, remote MCP, and signed receipts remain outside this alpha.
- Native mode trusts the host; a malicious container host administrator remains outside the Linux container threat boundary.

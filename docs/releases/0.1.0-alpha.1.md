# Review-LSP 0.1.0-alpha.1

Status: PUBLISHED PUBLIC ALPHA.

## Purpose

Review-LSP gives AI/code-review consumers semantic LSP context for an exact Git commit rather than whichever checkout is currently live.

The alpha proves the A/B case: commit A exports a string, commit B later changes it to a number, the live checkout stays at B, and a query bound to A still returns A semantics with a candidate/environment receipt.

## Included

- TypeScript hover and definition.
- Git-object candidate materialization.
- Content-addressed candidate/profile/environment/query receipts.
- Independent receipt validator.
- CLI and MCP stdio surface.
- Bundled package CLI and artifact manifest.
- TRUSTED_LOCAL native mode.
- Linux CONTAINER_READ_ONLY profile with exact Docker image identity.
- OpenCodeReview/Workbench consumer admission implemented separately and dogfooded before publication.

## Install

```bash
npm install review-lsp@alpha
```

For this first publication, npm currently exposes both `alpha` and `latest` as 0.1.0-alpha.1. Publication used `--tag alpha`, and npm documentation says an explicit publish tag should be used instead of the default `latest`; the additional `latest` tag is therefore recorded as an unexpected registry state. Deleting it returned HTTP 400. Intentional prerelease installs should use `@alpha`, and the first stable release should move `latest` to the stable version.

## Known limitations

- Only self-contained TypeScript projects can currently reach environment_binding=VERIFIED without additional limitations.
- Declared package dependencies are not snapshot-prepared yet and make environment_binding=PARTIAL.
- Native mode detects candidate mutation before/after requests but is not equivalent to a hostile-host sandbox.
- Definition targets outside admitted source/toolchain roots are UNBOUND and degrade environment evidence.
- Receipts are tamper-evident hashes, not signatures and not proof that semantic answers are correct.

## Local benchmark observation

Observed on macOS arm64, Node 24.19.0, 5 iterations:

- cold candidate preparation: ~474 ms;
- profile admission: ~147 ms;
- session start median: ~233 ms, p95 ~282 ms;
- hover median: ~650 ms, p95 ~687 ms;
- definition median: ~312 ms, p95 ~325 ms.

These are observational numbers from one machine, not release thresholds or cross-platform guarantees.

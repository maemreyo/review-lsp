# Review-LSP 0.1.0-alpha.3

Status: PUBLIC ALPHA once the exact release commit passes the compatibility matrix and is published under the alpha dist-tag.

## Purpose

Alpha.3 is a focused dependency-acquisition correctness release. It enables exact pnpm projects whose frozen lockfiles contain candidate-local tarball dependencies, such as file:vendor/package.tgz, without widening authority to arbitrary local directories or build pipelines.

## Fixed

- Candidate-contained local .tgz files referenced by pnpm file: lockfile entries are now explicit dependency inputs.
- Tarball bytes participate in the dependency input identity, so changing a vendored artifact invalidates the snapshot.
- Acquisition materializes the admitted tarballs at their candidate-relative paths before pnpm fetch/install.
- Missing, escaping, ambiguous, absolute/non-portable, and non-tarball local file references fail closed.

## Security boundary

This release does not admit arbitrary local directories or package build scripts. Local file dependencies are accepted only when they resolve uniquely to candidate-contained .tgz artifacts. Acquisition continues to use the exact pnpm version, frozen lockfile, ignored lifecycle scripts, and the existing explicit network policy.

## Install

    npm install review-lsp@alpha
    npx review-lsp artifact-info

## Release gates

Publication is blocked unless all of these pass on the exact release commit:

- pnpm check;
- macOS 14 / Node 22.19 and 24.19 compatibility;
- Ubuntu 24.04 / Node 22.19 and 24.19 compatibility;
- Linux container isolation smoke;
- benchmark job;
- clean-install package smoke;
- real Workbench repository acquisition with candidate-local tarballs;
- independent code review of the release delta.

## Known limitations

- TypeScript is the only supported language profile.
- The dependency provider intentionally supports a strict pnpm-10/workspace/config subset and fails closed elsewhere.
- Non-tarball local file: dependencies remain unsupported.
- Arbitrary package build pipelines are not executed.
- Windows, remote MCP, signatures, and additional semantic operations remain outside this alpha.
- Receipts prove provenance/admission properties, not semantic correctness of the LSP answer or reviewed code.

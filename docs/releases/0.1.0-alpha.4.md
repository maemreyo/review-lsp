# Review-LSP 0.1.0-alpha.4

Status: PUBLIC ALPHA once the exact release commit passes the compatibility matrix and is published under the `alpha` dist-tag.

## Purpose

Alpha.4 expands the candidate-bound semantic review surface from hover/definition to references and document diagnostics without weakening provenance or environment admission.

References answer bounded “where is this used?” questions while binding declaration-inclusion policy and classifying returned targets against candidate source, dependency snapshots, derived artifacts, toolchain source, or unbound provenance.

Diagnostics answer “what deterministic diagnostics does the admitted semantic engine return for this exact candidate document?” They are document-scoped semantic evidence, not project-wide build correctness.

## Added

- Candidate-bound `references` across `SemanticSession`, CLI, Linux container execution, MCP stdio, and package exports.
- Explicit `includeDeclaration` binding in reference request/receipt identity.
- Per-reference provenance classification and fail-closed environment downgrade for unbound targets.
- Candidate-bound document `diagnostics` with a separate `review-lsp.diagnostics-receipt.v1`.
- Deterministic TypeScript 6 compatibility transport using the fixed synchronous tsserver diagnostic command set.
- TypeScript 7 native `textDocument/diagnostic` transport when the initialized server advertises `diagnosticProvider`.
- Normalized diagnostic severity/tags/ranges, deterministic ordering, related-information provenance, result digests, and explicit engine-full-document completeness.
- Dynamic diagnostics capability advertisement based on the initialized engine.
- Workbench/OpenCodeReview dogfood for both references and diagnostics through explicit external-provider admission.

## Security and evidence boundary

- Candidate/source integrity is checked before and after semantic queries.
- Diagnostics do not use bounded `publishDiagnostics` silence as a completion signal.
- Unsupported diagnostics transports fail closed.
- Related-document responses, malformed ranges, malformed transport results, widened/unchanged native reports, and timeout outcomes are rejected when they cannot satisfy the frozen authority contract.
- Related-information URIs use the same provenance classification model as other semantic targets.
- Linux diagnostics reuse the `CONTAINER_READ_ONLY` isolation contract without synthetic line/character coordinates.
- `environment_binding=VERIFIED` remains distinct from semantic toolchain alignment.
- Receipts prove provenance/admission properties, not semantic correctness of the language-server answer or reviewed code.

## Install

    npx review-lsp artifact-info

## Release gates

Publication is blocked unless all of these pass on the exact release commit:

- targeted references/diagnostics unit and TypeScript 6/7 differential acceptance tests;
- `pnpm check`;
- package, MCP stdio and cache-crash smokes;
- macOS 14 / Node 22.19.0 and 24.19.0 compatibility;
- Ubuntu 24.04 / Node 22.19.0 and 24.19.0 compatibility;
- Linux container isolation smoke including document diagnostics;
- benchmark job;
- real Workbench provider dogfood for references and document diagnostics;
- candidate-bound independent review of implementation and release-prep deltas;
- exact tag, GitHub prerelease, npm package and artifact-identity checks.

## Known limitations

- TypeScript is the only supported language profile.
- The dependency provider intentionally supports a strict pnpm-10/workspace/config subset and fails closed elsewhere.
- Symbols are deferred beyond Alpha.4.
- Diagnostics are document semantic evidence, not a project-wide compiler/build verdict.
- Arbitrary local-directory dependencies and package lifecycle/build pipelines remain unsupported.
- Windows, remote MCP and signed receipts remain outside this alpha.
- Native mode trusts the host; a malicious container host administrator is outside the Linux container profile threat boundary.

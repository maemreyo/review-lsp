# Review-LSP 0.1.0-alpha.6

Status: PUBLIC ALPHA once the exact release commit passes every required gate and is published under the `alpha` dist-tag.

## Purpose

Alpha.6 replaces path-proximity project routing with exact candidate-bound ownership evidence for a deliberately narrow TypeScript project-membership subset.

The release claim is:

> Exact candidate-bound TypeScript project ownership and semantic routing for the admitted `files/include/exclude/extends` subset.

Alpha.6 builds on Alpha.5 project-reference admission. A project-reference edge does not itself prove ownership; ownership is evaluated independently from admitted membership evidence.

## Added

- Deterministic `EnvironmentManifest.project_ownership` evidence with `NONE`, `BOUND`, and `UNSUPPORTED` states.
- Per-config ownership evidence including:
  - exact config SHA-256;
  - routable vs inheritance-only status;
  - routing relevance;
  - bounded relative-`extends` chain;
  - effective `files`, `include`, and `exclude` rule values plus declaration origins;
  - effective `allowJs` membership modifier and its explicit/default origin;
  - deterministic per-config membership SHA-256.
- Aggregate ownership-model SHA-256 bound into `environment_manifest_sha256`.
- Document routing states `RESOLVED`, `UNRESOLVED`, `AMBIGUOUS`, and `UNSUPPORTED`.
- Project-specific runtime/session reuse bound to resolving-project ownership identity.

## Exact ownership boundary

### `files`

Explicit `files` entries are exact membership after candidate-relative normalization and candidate-file validation. They remain explicit membership even when the extension would not be discovered by an `include` pattern.

### `include` / `exclude`

The admitted glob subset is intentionally small: literals, per-segment `*` and `?`, and recursive `**` as a complete segment.

`exclude` filters only membership derived from `include`. It does not remove explicit `files` membership.

Include-derived membership reproduces the extension boundary required by this frozen subset:

- TypeScript family: `.ts`, `.tsx`, `.mts`, `.cts`;
- JavaScript family: `.js`, `.jsx`, `.mjs`, `.cjs` only when effective `allowJs=true`;
- other extensions are not discovered through `include`.

`jsconfig.json` contributes TypeScript's implicit `allowJs=true` unless explicitly overridden. `allowJs` is admitted only because it directly changes include membership; Alpha.6 does not claim general `compilerOptions` modeling.

### Relative `extends`

Only candidate-contained relative `extends` chains are admitted. Effective fields retain the config where each field was declared, so inherited paths/patterns are resolved relative to the declaration origin rather than incorrectly rebased onto the child config.

Package-based/external `extends`, escaping paths, cycles, missing targets, malformed configs, and unsupported ownership constructs fail closed when routing-relevant.

## Routing behavior

For a queried candidate document:

- exactly one proved owner -> `RESOLVED`;
- no proved owner -> `UNRESOLVED`;
- multiple proved owners -> `AMBIGUOUS`;
- ownership cannot be proved inside the admitted subset -> `UNSUPPORTED`.

Alpha.6 never chooses an owner by nearest config, lexical order, config depth, reference direction, or other heuristic.

A `RESOLVED` semantic query must use a runtime/session bound to the same exact resolving-project identity. The receipt records the proven resolving project and ownership identity.

## Security and evidence boundary

- Config bytes consumed by ownership admission are read through retained-candidate integrity verification.
- Project-reference evidence and project-ownership evidence remain separate, independently content-addressed dimensions.
- A standalone non-routable `tsconfig.*.json` remains evidence but its unsupported constructs do not poison unrelated provable routing; a routing-relevant unsupported config still blocks strong admission.
- Ambiguous ownership fails closed instead of silently selecting a project.
- `environment_binding=VERIFIED` remains an admission/provenance claim, not proof that the language server or reviewed code is semantically correct.
- Receipts remain tamper-evident rather than signed.

## Known limitations

- TypeScript is the only supported language profile.
- Ownership is supported only for the frozen Alpha.6 subset; TypeScript default file discovery is not claimed.
- Package-based/external `extends` is not admitted.
- Broader package `exports/imports`, workspace routing, and pnpm shapes remain separate hardening work.
- Arbitrary local-directory dependencies and package lifecycle/build pipelines remain unsupported.
- Symbols and project/workspace diagnostics remain deferred.
- MCP is local stdio only.
- Windows, remote MCP, and signed receipts remain outside this alpha.
- Native mode trusts the host; a malicious container host administrator remains outside the Linux container threat boundary.

# H3 status — CLI / MCP public interface

State: CLOSED for the v0.1 alpha support boundary.

> H3 was originally closed on the alpha.1 surface. The public CLI/MCP lifecycle remains current, while dependency-aware execution was expanded in alpha.2/alpha.3. For the current support matrix, see `docs/status/CURRENT.md`.

## Implemented

- CLI prepare/inspect/query/validate/close/serve.
- MCP stdio server bound to one candidate at launch.
- candidate_info, hover and definition tools.
- expected_candidate_id required on semantic query tools.
- MCP input buffer bound to 1 MiB.
- Candidate source file and total preparation bounds.
- Semantic document/result bounds from the pinned profile.
- Bounded LSP request/shutdown, process-group TERM/KILL cleanup on macOS/Linux.
- Fault-injection coverage for request timeout, late response, server crash, and close during an in-flight request.
- Unexpected language-server exit disposes the JSON-RPC connection so pending requests fail promptly.
- Clean MCP SDK client smoke: list tools, candidate_info, hover, mismatch rejection.
- Clean-install tarball smoke from an isolated consumer.
- Linux Docker profile:
  - candidate source bind-mounted read-only;
  - container root filesystem read-only;
  - network disabled;
  - all Linux capabilities dropped;
  - no-new-privileges;
  - bounded pids/memory/cpu;
  - writable state/tmp only through bounded tmpfs;
  - exact Docker image ID bound into the environment manifest;
  - inner process verifies /candidate is an explicit Linux read-only mount before emitting CONTAINER_READ_ONLY.
- stdout reserved for MCP; launcher/status output goes to stderr.

## Scope ceiling

H3 is CLOSED only for the local CLI/MCP lifecycle and the semantic operations explicitly exposed by the current release. It does not imply Windows support, remote MCP, dirty-worktree candidates, JavaScript support, or arbitrary dependency/project-shape completeness. The admitted pnpm dependency-snapshot/projection path implemented after alpha.1 does not widen those unrelated claims.

# H1 status — Candidate & environment

State: PARTIAL for general projects; VERIFIED for the admitted TypeScript dependency-aware subset.

## Implemented

- Git ref resolves once to commit/tree object IDs.
- Source bytes come from Git object DB, not live checkout.
- Manifest binds path/mode/blob/content digest/size.
- Rejects submodules, unresolved LFS pointers, non-canonical paths, case collisions, escaping/missing/cyclic symlinks.
- Managed candidate root is made read-only in TRUSTED_LOCAL mode.
- Full path/byte integrity verification before/after semantic queries.
- Content-addressed candidate descriptor validation.
- Explicit candidate cleanup restores owner write permission only inside the managed candidate directory.
- Source size/entry resource bounds.
- TypeScript environment manifest binds server/compiler package digests, source configs, OS/arch/node, isolation kind, isolation identity, and limitations.
- Linux container profile binds an exact Docker image ID and enforced read-only candidate mount on the supported Linux evidence lane.
- Content-addressed pnpm 10 dependency input derivation and explicit acquisition.
- Sealed dependency snapshots and source/dependency execution projections.
- Workspace entry-point completeness gates plus constrained derived TypeScript declarations.
- Candidate-selected TypeScript engine admission where the execution profile can enforce the required policy.
- Candidate-local frozen-lockfile `file:` dependencies are admitted only when they resolve uniquely to candidate-contained `.tgz` artifacts.
- Missing, escaping, ambiguous, unsupported package/workspace/config/build inputs remain PARTIAL or UNSUPPORTED; they are never promoted to VERIFIED by query success.

## Alpha support boundary

For the current alpha, `environment_binding=VERIFIED` is available only when all semantic inputs required by the active TypeScript profile are admitted and re-verifiable.

For dependency-bearing repositories that means, as applicable:

- supported pnpm 10 dependency inputs;
- a satisfied explicit acquisition state;
- sealed dependency snapshot;
- bound execution projection;
- complete workspace entry-point gate;
- admitted config/derived-artifact path;
- admitted semantic engine/execution profile.

A repository that declares dependencies is not automatically PARTIAL anymore. The binding is determined by whether its exact semantic inputs fit the admitted subset.

## Remaining before H1 is CLOSED for general projects

- stronger effective-config analysis across more TypeScript config shapes;
- project references and broader workspace routing;
- broader package `exports`/`imports` shapes where exactness can be preserved;
- broader pnpm project shapes backed by exact evidence;
- separate authority design for arbitrary local-directory dependencies;
- separate authority design for arbitrary package build pipelines;
- additional language/package-manager profiles only when equivalent provenance can be maintained.

These are general-project completeness items, not permission to silently widen the current support claim.

# H1 status — Candidate & environment

State: PARTIAL for general projects; VERIFIED vertical slice for self-contained TypeScript projects.

## Implemented

- Git ref resolves once to commit/tree object IDs.
- Source bytes come from Git object DB, not live checkout.
- Manifest binds path/mode/blob/content digest/size.
- Rejects submodules, unresolved LFS pointers, non-canonical paths, case collisions, escaping/missing/cyclic symlinks.
- Managed candidate root is made read-only in TRUSTED_LOCAL mode.
- Full path/byte integrity verification before/after semantic queries.
- Content-addressed candidate descriptor validation.
- Explicit candidate cleanup restores owner write permission only inside the managed candidate directory.
- Source size/entry resource bounds.
- TypeScript environment manifest binds server/compiler package digests, source configs, OS/arch/node, isolation kind, isolation identity, and limitations.
- Linux container profile can bind an exact Docker image ID and enforced read-only candidate mount once its CI acceptance passes.
- Missing package dependencies or external configs remain PARTIAL; they are never promoted to VERIFIED review evidence by consumers.

## Alpha support boundary

For v0.1 alpha, environment_binding=VERIFIED is claimed only for self-contained TypeScript candidates whose effective config and semantic inputs are fully admitted by the current profile.

Projects declaring package dependencies are still queryable when useful, but are explicitly marked environment_binding=PARTIAL because dependency snapshot preparation/admission is not implemented yet.

## Remaining before H1 is CLOSED for general projects

- Admitted dependency snapshot preparation/mounting for dependency-bearing repositories.
- Stronger effective-config analysis for all TypeScript config paths and generated declarations.

These are post-alpha/general-project completeness items, not permission to silently widen the v0.1 support claim.
